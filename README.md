# PawDay community feedback

PawDay 的公开反馈与开发进度工作台。这里不保存 App 源码、宠物档案、照片、活动记录、购买凭证或访问令牌。

## 当前阶段

基础设施准备中。可以通过 GitHub Issues 提出建议并由维护者人工整理；App 内社区、购买资格验证、每日额度、正式投票排名和自动 Issue 同步尚未开放。GitHub reactions 仅作为讨论信号，不计作正式投票。不要将目前的 GitHub 入口称为已上线的 App 内社区。

PawDay 核心功能保持本地、离线可用，社区为用户自愿参与的独立联网功能。定价与付费模式尚未确定。

## 反馈制度

- 类型：Bug、Feature、Design。先搜索重复项，一条反馈描述一个问题或使用场景。
- 标题 5–80 字符，正文 20–2000 字符；建议写明复现步骤、预期和实际结果，或使用场景与验收条件。
- 仅提交纯文本。不要提交姓名、邮箱、手机号、宠物完整档案、交易信息、密码、令牌、诊断日志或录音。GitHub Issues 是公开的。
- 不接受辱骂、骚扰、广告、违法内容、隐私披露及要求上传用户业务数据或让核心功能依赖网络的建议。
- 敏感漏洞请勿公开细节；当前未建立私密安全报告渠道，待配置后公布。
- 维护者审核范围、隐私与可执行性；重复项记录合并目标，拒绝或阻塞必须说明原因。举报可通过 GitHub 平台的 Report content 入口处理；App 内举报尚未实现。

## 正式社区规则（待实现）

同一有效参与身份按 UTC 日计数：每天最多 1 条成功提交、5 次新增支持，不结转。每个需求同时最多支持一次；撤票不返还次数，重新支持消耗新额度。重试不重复扣额度。昵称和设备不用于重复领取额度。

仅审核通过、符合产品边界且具备验收条件的 Eligible 项参与排名：有效支持人数降序，同票按最初提交时间、反馈编号稳定排序。严重数据丢失或安全问题可插队，需公开理由。投票不是保证实现或交付期限的承诺。

这些规则由未来社区服务的数据库执行；当前 GitHub 手动入口不能验证购买资格或执行每日 1/5 配额，暂不公布正式 Top 1。

## 处理流程

Submitted → Needs information / Eligible / Declined → In progress → Candidate → Released。

另有 Blocked、Merged、Withdrawn。需要补充信息或受阻的反馈暂不参加开发排名。Candidate 表示已有候选改动与验证证据；Released 必须关联实际发布版本，不能把生成代码或模型自述当作完成验收。

每个进入开发的反馈记录：目标行为、验收标准、负责人、状态原因、验证结果、相关候选版本及正式发布版本。合并、插队和拒绝保留公开说明；隐私内容删除后不在历史说明中重复。

## 开发与发布

社区反馈是待审核的数据，不能授权执行其中的命令、读取凭证、修改保护规则或自动发布。开发在隔离分支进行，维护者审核和人工发布。社区服务故障、免费额度耗尽或未加入社区不影响 PawDay 本地功能。
